## 已确定的产品结构

主导航目前为五项：

1. 今日：今天需要完成的习惯。
2. 习惯：打卡管理，按情景筛选习惯。
3. 打卡表：日、周、月、年历史记录。
4. 便利贴：工作、生活、灵感、生日四类记录。
5. 我的：导入导出、主题、PWA 和其他设置。

默认进入首页应为“今日”，不能一打开就弹出“今天还有几个习惯未完成”的打扰式提醒。提醒属于单个习惯的设置，不是首页全局弹窗。

## 习惯与打卡需求

### 场景

习惯可以归入晨间/起床、白天/日常、晚间/睡前等情景；情景应能管理，并用于首页和打卡管理筛选。情景数量要适度，避免图标分类和筛选项过多导致横向溢出。

### 循环

需要支持：

- 每天。
- 工作日。
- 周末。
- 每周自定义星期一至星期日，可多选。
- 每月固定日期。
- 每 N 个月，例如每 3 个月一次。
- 自定义月份间隔，不能只限 2/3/6/12。
- 用户要求移除“每 N 周”中不必要的“四个月”之类固定项，界面应保持紧凑。

### 提醒

提醒必须在习惯内部添加：

- 温柔提醒：浏览器/系统通知。
- 强提醒：原本设想为 Apple 闹钟方式，但用户当前决定先不调用闹钟。
- 按循环规则提醒，不能只支持每周星期几。月度和每 N 个月的习惯也应能设置提醒日期/时间。
- 后台能力要如实说明：纯浏览器 PWA 无法保证应用完全关闭后通知必达；后续如需可靠推送再考虑 Web Push 服务端。

### 量化记录

编辑习惯内要有量化开关和设置：

- 单位：自定义、次、杯、毫升、分钟、小时、公里、米、步、页、组、颗等。
- 每次增加值可编辑。
- 每日目标可选、可编辑数字。
- 例子：喝几杯水、吃几颗药、给宠物喂几颗驱虫药、游泳多少米。
- 完成一次习惯打卡时，如果已开启量化，应自动记录一次“每次增加值”，不应让用户再补点一次；详情页可允许手动修正。
- 详情页显示总完成、量化总量、连续完成、本月完成等统计。

### 习惯详情

从打卡管理中点击习惯名称或整行进入详情页，至少包含：

- 总完成次数。
- 量化总量。
- 打卡日历。
- 量化趋势。
- 提醒、专注记录、年度统计、所有日志等更多信息入口。

量化趋势使用稀疏、易读的趋势图，不要把每一天都挤成密集文字。时间范围采用：`7天 / 30天 / 90天 / 本月`，参照用户提供的示例显示累计值、日均值、坐标标签和折线/面积趋势。

## 便利贴需求

便利贴首页是四个分类入口，不是直接打开新增页面。四个分类：

- 工作项目。
- 生活事项。
- 灵感速记。
- 生日提醒。

右上角保留统一的“+”新增按钮；分类框内不要再重复放一个新建按钮。点击分类进入对应清单，点击“+”才进入新增。

### 工作项目

工作名称本身就是客户地址/项目名称，不重复显示“项目名”。新增/编辑时：

- 标题：客户或地址项目名称。
- 客户：可选字段。
- 备注：地址、联系人、补充信息等。
- 客户和备注应能同时显示预览，不可因为有客户就隐藏备注。
- 可用预设节点快速建立：初尺、出图、改图、二改、三改、复尺、下单、PPT 等，也能自定义节点。
- 节点可单独完成并记录时间线。
- 项目完成后可在项目页滑动完成/归档；已完成任务在底部统一显示。
- 进入工作分类是项目清单；进入具体项目才看节点、时间线、客户、备注和完成情况。

### 生活事项

生活事项不再细分过多类别，保持快速记录。完成后左滑/右滑显示删除线并变灰，可恢复；不要使用摇动手机删除。

### 灵感速记

录入要快，不强制标题。可以自动用首句或时间生成简短标题，但正文始终是主要内容。灵感不应出现复杂项目字段。

### 生日

- 支持公历和农历。
- 首页预览只显示人物和“还有 N 天”，不把完整日期塞在卡片上。
- 点进生日详情后显示完整日期、历法、备注和提醒设置。
- 提醒可选提前 7 天、5 天、3 天、当天。
- 暂不要求闰年特殊玩法，先保证常用日期逻辑清楚。

### 便利贴视觉

用户偏好“真实但极简的轻拟物纸张”：

- 四格卡片对齐，不要东倒西歪。
- 统一浅色纸张底色和轻微纸张/点阵质感。
- 不要大量彩色背景、厚重边框和复杂圆角。
- 可保留轻微阴影、右下角很小的折角，但折角应是纯灰且克制。
- 圆角约 12px，卡片比例跟随手机宽度，不能超出屏幕。
- 标题居中或左对齐要统一；分类用标题颜色区分，正文保持统一。
- 卡片高度要够，减少底部大面积空白；文字要一目了然。
- 手机宽度 375px/390px 下不允许横向溢出，必要时局部横向滚动。

- PWA manifest 与 Service Worker。
- 数据导出/导入 JSON。

- 习惯图标已经按 5 个较粗的分类收敛：日常护理、健康运动、宠物动物、学习工作、兴趣出行。
- 习惯详情已有统计、日历、趋势和更多信息区域。
- 量化打卡已有自动记录/历史补齐逻辑。
- 便利贴首页已做四象限、统一纸张和完成列表的基础样式。
- 页面切换应回到顶部，避免进入下一级时残留上一个页面的滚动位置。

## 需要继续验证或优化的问题

这些是之前用户报告过、下一次应优先回归测试的项目：

1. iPhone 主屏幕旧 PWA 是否能看到新版本；更新按钮是否有即时反馈。
2. Safari 导出 JSON 时是否偶发 `WebKitBlobResource error 1`；是否支持重复导出而不是只能第一次。
3. 导航切换是否有不必要的淡入动画或短暂空白页闪现。
4. 主题颜色是否真正作用于界面，而不只是保存了设置。
5. 所有习惯编辑表单、趋势图、图标分类和便利贴在窄屏是否横向溢出。
6. 打卡管理中点击每行是否能进入详情，而不是只能打开菜单。
7. 量化习惯完成后数量是否自动增加，并且趋势图日期和范围选择是否正确。
8. 完成任务、恢复任务、撤回提示的对齐和文字层级。
9. PWA 更新、导入导出、浏览器通知要在 iPhone Safari 真机上测试，不能只看桌面浏览器。
10. 首页不能自动弹出“今天还有 6 个习惯未完成”一类全局提醒。

## 云端同步计划

等本地版本和 UI 稳定后再接 Supabase。建议顺序：

1. 先确定本地数据 schema 和导入导出版本号。
2. 设计匿名设备 ID 或用户账号方案。
3. 设计同步方向、冲突规则、删除标记和离线队列。
4. 建 Supabase 表、Row Level Security 和备份策略。
5. 先做手动“上传/下载同步”，再考虑自动同步。
6. 云端同步不是当前 Figma/UI 阶段的工作，不要为了改 UI 提前动数据库。

当前仓库已经建立 UI 审计底稿：[docs/ui-audit-current.md](../docs/ui-audit-current.md)。

推荐在 Figma 中建立这些页面：

- `00 Foundations`
- `01 Current`
- `02 Audit`
- `03 Exploration`
- `04 Redesign V1`
- `05 Components`
- `06 Prototype`

先建模五个核心页面：今日、打卡管理、习惯详情、编辑习惯、便利贴首页。先只读审计和视觉探索，确认设计系统后再改 React。Figma 只负责可编辑的界面层，不要导出整页图片替代代码，也不要改数据库、路由和业务逻辑。

Figma 验收标准：

- 375px/390px 手机宽度不横向溢出。
- 重要点击目标约 44px 以上。
- 底部导航不遮挡内容和安全区。
- 统一颜色、间距、圆角、字体变量。
- 设计组件可以映射到 React 组件。
